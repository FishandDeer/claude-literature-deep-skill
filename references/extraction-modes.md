# 三种工作模式详细判别与执行细则

本文档是 SKILL.md「核心原则」的展开。在动手前必须确认模式;模式之间互不混淆。

---

## MODE-A 逐字摘抄(Verbatim Extraction)

### 定义

把源文献(或源 markdown 总结)中的目标章节,**100% 原封不动**地复制到输出文档。零改写、零归纳、零删减、零重组、零重新分段。

### 何时触发

用户原文出现以下任一表述:

- 「摘抄」「直接摘抄」「直接复制」「原文」
- 「不要总结」「不要归纳」「不要改写」
- 「我自己用来写 PPT/论文」「给我素材」「保留原始信息」
- 「我能够直接复制到我的 PPT 上」

### 执行步骤

1. **不要人手挑选要点**。人手处理一定会偷偷归纳,这是不可避免的认知惯性。
2. **必须用脚本抽取**。调用 `scripts/extract_sections.sh`,按关键词 fuzzy match 抽取章节,直接拼接。
3. **按论文逐篇组织输出**:
   ```markdown
   ## #1 — [论文标题]
   **源文件**: `xxx.md`
   ### 研究背景(原文逐字摘抄)
   <脚本抽取的原文>
   ### 相关工作(原文逐字摘抄)
   <脚本抽取的原文>
   ---
   ## #2 — [论文标题]
   ...
   ```
4. **绝对禁止**:按 PPT 页重组、按主题/范式重组、按"我觉得 PPT 用得上"挑选。

### 失败信号 → 立即切换重做

- 用户说「我需要的是直接摘抄,你还在总结归纳」
- 用户说「你没有理解我的需求,我要的是这篇文献中的研究背景和相关工作」
- 用户说「你提供的都是精炼点,我还需要自行叙述」

→ 此时**不要解释**,直接用脚本重做并交付。

### 输出文件命名建议

- 单文献:`<paper-slug>_verbatim_<section>.md`(如 `coViT_verbatim_background.md`)
- 多文献汇编:`literature_<section>_verbatim.md`(如 `literature_background_related_work.md`)

## MODE-B 归纳总结(Structured Summary)

### 定义

阅读原文后,**用自己的话**重新组织,产出结构化的中文摘要文档。是 `paper-summarizer` 的标准模式。

### 何时触发

- 「总结」「归纳」「摘要」「概述」
- 「帮我看看这篇讲了什么」「读一下这篇」
- 「做成一份总结报告」

### 标准模板

详见 `references/summary-templates.md`。核心结构:

```
1. 基本信息表(标题/作者/单位/发表/DOI/任务/数据集/硬件)
2. 一句话摘要(TL;DR ≤ 50 字)
3. 研究背景与动机
4. 核心贡献
5. 方法论
6. 实验结果(数据集 + 主要结果 + 消融)
7. 局限性
8. 个人点评
9. 关键词
10. 相关工作
```

### 执行原则

- **保留原文细节**:数字、年份、数据集名、模型名一律照搬,绝不用"等"省略
- **中文优先**,英文术语保留(VLM、CLIP、LoRA、SAE J3016 等不翻译)
- **每篇文献一个独立 .md**,放在用户指定目录(默认与源文件同目录)
- **批量处理**(≥3 篇)时,额外输出 `00-OVERVIEW.md` 总览索引(主题分类 + 一句话速览表)

### 不要做的事

- ❌ 把 5 段方法论压缩成一句"方法巧妙"
- ❌ 隐去具体数据集名,只写"在多个数据集上验证"
- ❌ 隐去具体数值,只写"取得了显著提升"

## MODE-C 完整段落叙述(Narrative Document)

### 定义

基于一篇或多篇文献的素材,**用完整的段落**写成可直接作为论文章节/汇报正文/技术博客的连贯长文。

### 何时触发

- 「完整叙述」「不要只给论点」「写成文章」「写成段落」
- 「做成研究背景章节」「做成 related work 章节」
- 「我需要文字的完整叙述」(本会话用户原话)

### 写作原则

1. **每节由 2~5 个完整段落组成**,而不是 bullet list
2. **数据嵌入文中**:用「NHTSA 2021 年报告显示美国当年因分心驾驶造成 3522 人死亡[#1]」这种行文方式,而非「• 美国 3522 例 [#1]」
3. **引用编号 `[#N]`** 必须与源文档一致
4. **起承转合**:每节首段引入主题,中间段落展开,末段做小结或引出下节
5. **学术语气**:克制,避免营销话术(如「颠覆性」「革命性」)、避免口语化(如「我觉得」「其实」)

### 推荐结构(以"研究背景"为例)

```markdown
# 题目

## 一、引言:为什么 X 在 Y 时间窗口突然成为焦点
(2~3 段定义、范畴、本节脉络)

## 二、事故/数据/问题驱动
### 2.1 全球性数据
(完整段落叙述,而非 bullet)
### 2.2 区域细分
### 2.3 新型问题

## 三、法规/标准/政策驱动
### 3.1 欧盟
### 3.2 美国
### 3.3 中国
### 3.4 国际共识

## 四、产业落地
## 五、学术驱动
## 六、共识与挑战
## 七、结语
```

### 失败信号

- 用户说「不要只给论点」「我需要的是文字的完整叙述」
→ 重写时把所有 bullet 改为完整段落,并补充上下文连接句

## "全套" 混合模式(用户常见的隐含期望)

许多用户的实际期望是「先 MODE-B 帮我搞清楚每篇讲了什么,再 MODE-A 给我原文素材以便我自己写 PPT,最后 MODE-C 帮我写一份组会报告的研究背景章节」。这是一个 B→A→C 的工作流。如检测到这种需求,**主动用 AskUserQuestion 确认**是否要全套交付,以及交付顺序。
