# 学术 PPT 视觉规范与版式

> 适用场景:中文学术汇报、组会、论文阅读会、开题/中期/答辩。**英文国际会议 PPT 不在本规范范围内**。

---

## 一、基础参数

| 参数 | 值 |
|---|---|
| 比例 | 16:9(`Inches(13.333, 7.5)`) |
| 中文字体 | Microsoft YaHei(首选)→ Noto Sans CJK SC(Linux fallback)→ SimHei |
| 英文/数字字体 | Calibri 或 Arial(与中文同行混排不至于错位) |
| 标题字号 | 32~36 pt |
| 正文字号 | 18~22 pt(章节页正文 22,内容页 18~20) |
| 注释/页脚 | 12~14 pt |
| 行距 | 1.2~1.3(纯英文 1.15) |

---

## 二、配色

**深蓝主色 + 橙色强调**,这是经过多次组会反馈验证的"学术、克制、不土"的组合。

| 用途 | RGB | 十六进制 |
|---|---|---|
| 主色(标题、章节条) | (31, 56, 100) | `#1F3864` |
| 副色(副标题、强调框边) | (47, 85, 151) | `#2F5597` |
| 强调色(关键数据、引用编号) | (237, 125, 49) | `#ED7D31` |
| 文字正色 | (51, 51, 51) | `#333333` |
| 文字次色 | (102, 102, 102) | `#666666` |
| 背景 | (255, 255, 255) | `#FFFFFF` |
| 分隔线 / 浅色背景 | (217, 226, 243) | `#D9E2F3` |

**禁止**:
- 深色背景(看着累、投影仪偏色严重)
- > 5 种颜色出现在同一张 slide(评委会觉得花)
- 红色用于强调(易与"错误"语义混淆,改用橙)

## 三、版式模板(必备 8 类)

| 版式 | 用途 | 关键元素 |
|---|---|---|
| **封面页** | 第 1 页 | 大标题(主题)+ 副标题(场合)+ 汇报人 + 日期 + 单位 logo(右下) |
| **目录页** | 第 2 页 | 章节列表 + 编号圆点,**不要写"目录"两个字标题** |
| **章节扉页** | 每章首页 | 大号章节编号(64 pt)+ 章节名(36 pt)+ 一句话本章主旨 |
| **内容页(标准)** | 主体 | 顶部标题条(深蓝)+ 内容区(分栏或图文混排) |
| **图表强调页** | 展示数据 | 顶部小标题 + 中央大图/表 + 底部一句话结论 |
| **对比页** | 二/三方对比 | 顶部标题 + 2~3 列等宽 + 列内 5~7 行 |
| **引用/参考页** | 文献来源 | 标题"参考文献" + 编号列表 + 12 pt 字号 |
| **结尾页** | 致谢/Q&A | 大字"谢谢" / "Q&A" + 联系方式 |

---

## 四、Action Title(行动式标题)

每张内容页的标题必须传达**结论**,而不是**主题**。

| ❌ 主题式 | ✅ 行动式 |
|---|---|
| "数据集" | "在 4 个公开数据集上验证,规模 2k~50k" |
| "实验结果" | "Top-1 准确率从 89.2% 提升至 94.7%" |
| "相关工作" | "现有方法在长尾分布下精度下降 12 pp" |
| "方法" | "通过 CBAM 双注意力实现跨模态对齐" |

---

## 五、内容密度

- **每页一个核心论点**。超过两个就分页。
- **正文 ≤ 6 行 / 页**;每行 ≤ 35 个中文字符或 70 个英文字符。
- **图 > 表 > 文字**:能用图就别用表,能用表就别用文字段落。
- **引用编号 `[#N]`** 用橙色加粗,放在被引论点末尾。

---

## 六、必须避免的"翻车现场"

| 现象 | 根因 | 对策 |
|---|---|---|
| 中文字符显示成方框 | Linux 端无 YaHei | 用 Noto Sans CJK SC,或预先 `apt install fonts-noto-cjk` |
| 文字溢出文本框 | 没估算字符数 | python-pptx 写入后用 `auto_size = MSO_AUTO_SIZE.SHAPE_TO_FIT_TEXT`,或人工检查 |
| 图片被拉变形 | 修改 width 没同步 height | 用 `from PIL import Image` 读原图比例,等比缩放 |
| 章节标题占整页一半还多 | 大字号 + 长标题没换行 | 标题 ≤ 16 个中文字符;超过的拆成主+副标题 |
| 上下页字体大小忽变 | 多人协作 / 模板 placeholder 没统一 | 用脚本统一 `run.font.size = Pt(20)` |
| 配图分辨率糊 | 截图低 dpi | 来源图用 `pdftoppm -r 200`,自绘图用 mermaid → png 300 dpi |

## 七、推荐架构

### 7.1 paper-reading PPT(单篇文献,15~20 min)

1. 封面 — 论文元信息
2. 目录
3. 研究背景与动机(2~3 页)
4. 核心问题与挑战(1 页)
5. 方法框架(总览 1 页 + 细节 2~4 页)
6. 实验设置(1 页)
7. 主要结果(1~2 页表/图)
8. 消融实验(1 页)
9. 贡献总结(1 页)
10. 局限与展望(1 页)
11. 对我们项目的启示(1 页,**这是组会要的核心**)
12. Q&A

### 7.2 综述报告 PPT(批量文献,25~40 min)

1. 封面
2. 目录(按"研究背景 → 现有工作 → 共识与空白 → 研究问题")
3. 研究背景:数据/法规/产业三重驱动(3~5 页)
4. 现有工作分类(按范式分阵营,2~3 页)
5. 每阵营代表论文逐一速览(每篇 1 页)
6. 跨论文对比(1~2 页大表)
7. 共识与空白(1 页四象限或四共识 + 三空白)
8. 研究问题切入(1 页)
9. 参考文献
10. Q&A

## 八、与 `scripts/build_pptx.py` 的关系

`scripts/build_pptx.py` 已经把以上规范固化为函数(`add_section_header`, `add_content_slide`, `add_compare_slide` 等)。**生成 PPT 时优先调用这些函数,不要从 `Presentation()` 裸写**——否则一定会违反本规范的某一条。

如确需新版式,先在本文件添加规范,再去脚本里补函数,**禁止反向**(先写代码再补文档)。
