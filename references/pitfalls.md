# 历史踩坑清单与自检 Checklist

> 本文件是「过去做错了什么」的实录。每次完成交付前必须按附录 checklist 逐项打勾。
> **新出现的失败案例必须立即追加到本文件**——这是本 skill 不再重复踩坑的唯一机制。

---

## 一、需求理解类(最致命)

### 案例 1.1:未问模式直接动手,V1→V4 反复返工

- **现象**:用户说"帮我处理这些文献做 PPT 素材",我默认按 MODE-B(总结归纳)产出了 737 行;退回后改为 MODE-A 按 PPT 页重组(447 行),再退回;再改为半摘抄(653 行),仍退回;最后改为完全逐字摘抄(1057 行)才被接受。
- **根因**:省略了 Step 1 的 AskUserQuestion,凭"PPT 素材→应该是要点"的惯性推断模式。
- **用户原话**(三次失败的关键反馈,必须背下来):
  1. "我需要的是直接摘抄,而你还是进行了总结归纳"
  2. "你没有理解我的需求,我要的是这篇文献中的研究背景和相关工作"
  3. "你提供的都是精炼点,我还需要自行叙述"
- **教训**:即使用户原始指令看起来明确,**只要存在 MODE-A/B/C 歧义,必须问一次**。问一次的代价是 30 秒,不问的代价是 4 次返工。

### 案例 1.2:把"完整叙述"理解成只要 bullet

- **现象**:用户说"总结一下全球对于 DMS 系统的重视情况",我给了一份 bullet point 列表。
- **退回反馈**:"生成一份文档,注意,**不要只给论点,我需要的是文字的完整叙述**"
- **教训**:用户说"叙述""文档""文章"时,产出必须是**完整段落**,不是 bullet。bullet 是给自己用的提纲,不是给读者用的叙述。
- **判别口诀**:"给我看的是提纲,给读者看的是段落"。

### 案例 1.3:默认输出语言

- **现象**:源文献是英文,我用英文输出总结。
- **退回反馈**:"我需要的是中文"
- **教训**:**中文是默认**,无论源文献是什么语言。英文术语保留(VLM、CLIP、Transformer、SAE J3016、Euro NCAP 等),但叙述用中文。

## 二、抽取脚本类

### 案例 2.1:只匹配阿拉伯数字编号,漏掉 1/3 文献

- **现象**:V4 第一版用 `awk '/^## 3\./,/^## /'`,只匹配 `## 3. 研究背景` 这种形式。结果 18 篇里有 5 篇章节为空,因为它们用的是 `## 三、研究背景(Background)`。
- **根因**:不同作者写 markdown 总结时,编号风格不统一(见 [[section-mapping]])。
- **修复**:改用 `awk -v key="研究背景" '...index($0, key) > 0...'` 关键词模糊匹配,完全无视编号。
- **教训**:**抽取脚本永远不要依赖数字编号**,只用关键词文本。

### 案例 2.2:#13 文献仍为空(关键词不完整)

- **现象**:修复 2.1 后,#13 `vlms-identify-distracted-driver-naturalistic-videos.md` 的研究背景仍是空白。
- **根因**:这一篇用的是 `## 背景与动机 (Background & Motivation)`——**没有"研究"前缀**,所以 `index($0, "研究背景")` 仍然不命中。
- **修复**:给 `extract_section` 加 fallback key 参数,调用为 `extract_section "$src" "研究背景" "背景与动机"`。
- **教训**:**永远准备一个 fallback 关键词**。see [[section-mapping]] 中每个章节的别名表。

### 案例 2.3:`## 5. 方法论:HSUM 框架详解` 漏抽

- **现象**:精确匹配 `## 5. 方法论$` 时,这种带冒号 + 子标题的标题不命中。
- **修复**:`index($0, "方法")` 包含式匹配。
- **教训**:**永远用 `index()` 而非 `==` 或正则锚定**。

## 三、输出组织类

### 案例 3.1:把多篇文献按 PPT 页重组

- **现象**:用户要"PPT 素材",我把 18 篇文献的研究背景按"事故数据 / 法规 / 产业"等主题打散,重组成 PPT 页。
- **退回反馈**:用户要的是**按文献逐篇**的素材包,自己再去挑去重组,不需要我替他重组。
- **教训**:**MODE-A 必须按文献逐篇组织**,绝不按主题/页面/范式重组。重组是用户自己的工作。

### 案例 3.2:省略具体数据

- **现象**:写"NHTSA 2021 美国约 3000 多例分心致死"。
- **正确**:"NHTSA 2021 美国 **3522 例**分心致死"。
- **教训**:**数字一律照搬原文**,不要用"约""多""左右"模糊化。年份、数据集名、模型名同理,不要写"等"。

## 四、PPT 生成类

### 案例 4.1:从零手写 python-pptx,配色违和

- **现象**:不读 [[ppt-design]],直接 `from pptx import Presentation` 裸写,配色用默认蓝绿,字体用默认 Calibri,中文显示成方框。
- **教训**:**禁止裸写 python-pptx**。先看 [[ppt-design]],用 `scripts/build_pptx.py` 提供的封装函数。

### 案例 4.2:Linux 端中文乱码

- **现象**:在服务器上生成的 PPT,Windows PowerPoint 打开后中文是方框。
- **根因**:Linux 端缺少 Microsoft YaHei 字体,python-pptx 不会自动 fallback。
- **修复**:`apt install fonts-noto-cjk`,在脚本里同时指定 `font.name = 'Microsoft YaHei'`(Windows 端有效)和确保 Linux 端嵌入字体。

### 案例 4.3:把"摘抄"内容直接塞进 PPT

- **现象**:MODE-A 抽出的原文段落直接 copy 到 slide 的 textframe,文字溢出 + 字号过小。
- **教训**:**MODE-A 的原文是给用户去 PPT 写作的素材,不是 PPT 内容本身**。要做 PPT 还是要走 MODE-B 或 MODE-C 的精炼路径。

## 五、交付前自检 Checklist

每次交付前,逐项打勾。**任何一项未过,不要交付。**

### 5.1 模式一致性

- [ ] 是否在 Step 1 已与用户确认了 MODE?(MODE-A 摘抄 / MODE-B 总结 / MODE-C 叙述)
- [ ] MODE-A 产出里是否混入了"综上""总的来说""可以看出"这类归纳话术?
- [ ] MODE-C 产出里是否还有 bullet list 或纯数据表(应该全部转为完整段落)?
- [ ] MODE-A 是否按论文逐篇组织(`## #N — 标题`),而不是按主题重组?

### 5.2 章节抽取完整性

- [ ] 18 篇(或 N 篇)文献是否**每一篇**的目标章节都非空?(空白率必须 = 0)
- [ ] 抽取脚本是否用了关键词 fuzzy match,而非数字编号?
- [ ] 是否覆盖了 [[section-mapping]] 列出的所有别名?

### 5.3 数据保真

- [ ] 数字是否全部保留(年份、accuracy、数据集大小、参数量、训练时长)?
- [ ] 数据集名、模型名是否完整(没有"等""多个"等模糊化)?
- [ ] 引用编号 `[#N]` 是否与源文档一致?

### 5.4 语言与术语

- [ ] 输出是否中文优先?
- [ ] 英文术语(VLM、CLIP、Transformer、SAE J3016 等)是否保留原文,未强行翻译?
- [ ] 是否避免"颠覆性""革命性""极大提升"等营销话术?

### 5.5 PPT(如适用)

- [ ] 是否用 `scripts/build_pptx.py` 而非裸写?
- [ ] 中文在 Windows 端打开是否正常(不是方框)?
- [ ] 每页是否只有一个核心论点?
- [ ] 标题是否是行动式(传达结论)而非主题式?
- [ ] 文字是否溢出文本框?(用 PowerPoint 或 LibreOffice 实际打开检查)
- [ ] 图片是否被拉变形?
- [ ] 配色是否在深蓝+橙的范围内,没有 > 5 种颜色?

## 六、新增案例的录入模板

发生新失败时,**当场**追加到对应"一/二/三/四"小节,格式:

```markdown
### 案例 X.Y:[一句话症状]
- **现象**:[做了什么,结果是什么]
- **退回反馈**:"[用户原话,务必逐字]"
- **根因**:[为什么会这样]
- **修复**:[如何改的]
- **教训**:[下次怎么避免,要可执行]
```
